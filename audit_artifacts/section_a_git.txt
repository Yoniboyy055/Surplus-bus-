    Remediation: secure ownership APIs, env-safe middleware, and Phase‑1 opportunity intelligence
    
    ### Motivation
    - Close security and runtime gaps left by the previous launch patch by enforcing authenticated ownership on user-facing APIs and preventing middleware crashes when Supabase env vars are missing.
    - Deliver a concrete Phase‑1 Opportunity Intelligence foundation (scoring + personalization + ranked API) so the product can surface defensible, ranked signals rather than only raw data.
    - Harden ingestion agents with lifecycle logging, failure records, and schema validation so scraping runs are observable, replayable, and safe at scale.
    
    ### Description
    - Enforced ownership and role checks via a shared helper `requireUser`/`requireOperator`, and wired it into user APIs (`/api/alerts`, `/api/profile`, `/api/subscription`, `/api/analytics`, `/api/opportunities/*`) so callers cannot write arbitrary `profile_id` values.
    - Made middleware environment-aware so public pages render when Supabase env vars are missing and protected routes redirect with a clear config error instead of crashing; retained owner-role hardening and role-based route redirects.
    - Implemented Phase‑1 intelligence primitives in `lib/intelligence/scoring.ts` (demand/value/urgency, `computeScore`, `normalizeScore`, `personalizedScore`), an operator-only recompute job `POST /api/opportunities/recompute-scores`, and a personalized ranked endpoint `GET /api/opportunities/ranked`.
    - Added ingestion lifecycle and validation helpers (`lib/agents/ingestion.ts`) with `startIngestionRun`/`completeIngestionRun`/`queueCandidates` using `zod`, plus SQL migrations (`supabase/sql/015_public_launch_foundation.sql` and `016_opportunity_intelligence_phase1.sql`) to create `opportunities`, `opportunity_features`, `ingestion_runs`, `ingestion_failures`, and user preference fields/indexes.
    - Aligned UX and docs to the authority-first funnel: updated landing CTA to `Get Weekly Intelligence`, added the authority growth playbook and launch docs, and clarified health/queue behavior for agents.
    
    ### Testing
    - Ran `npm run lint` and it completed with no ESLint warnings or errors (pass).
    - Ran `npm run build`; production build completed successfully with expected environment-variable warnings about missing Supabase keys in this container (pass with env warnings).
    - Ran `npm run dev` and verified the app served `/landing` (HTTP 200) and a headless browser script captured a screenshot of the landing page (page render succeeded; screenshot artifact produced).
    
    If you want, I can next add unit tests for the scoring functions, a scheduled job to run `recompute-scores` in production, and a small integration test that seeds sample `opportunities` and verifies the ranked API ordering.
